# 角色素材槽位（用户本地导入）

这个目录存放**用户自己准备的角色美术素材**。它整体不进版本库、不进安装包：
模型、立绘和背景的版权与授权由素材提供者负责，仓库只保留本说明与目录骨架
（见 `docs/progress.md` 的 R10 与 D57）。

一层目录 = 一个人设，目录名必须与 `data/personas/<persona_id>/` 一致。
默认人设是 `remielle`。

```
data/assets/
  <persona_id>/
    avatar.png          # 头像 / 立绘：png · webp · jpg，用于主界面、设置、管理台的头像位与托盘图标
    background.jpg      # 可选：该角色的窗口背景图（主窗、设置、管理台；浮窗仍为透明）
    live2d/
      model3.json       # Live2D 模型入口 = 桌面浮窗（桌宠）本体，.moc3 / 贴图 / 物理 / 表情文件放同目录
```

约定：

- 文件名固定，一个角色一份当前生效素材；换角色 = 切换人设，不引入索引清单文件。
- 只读，不写回：程序不会生成、改名或清理这里的文件，删除即彻底删除（与记忆导出/删除同一边界）。
- **三类素材互不兜底**（2026-10-30 决定，见 `docs/progress.md` 的 D58）：`live2d/` 决定桌宠是否存在——模型缺失、损坏或 WebGL 不可用时**桌宠功能直接失效**，浮窗不显示并在设置页与 `doctor.py` 说明原因，**不会**退回 `avatar.*`，也不会退回任何内置形象；`avatar.*` 缺失只让头像位留空；背景缺失才回退主题纯色（"没有背景图"是正常配置，不是故障）。
- 当前状态（2026-10-30）：**仅预留位置**。读取、`/api/asset` 路由与设置页选图登记为 M13.1/M13.2，Live2D 载体的接入与旧程序化形象的删除登记为 M13.3，均尚未实施；把素材放这里还不会生效。实施顺序是 M12 剩余切片（M12.3 → M12.4 → M12.5）全部做完之后才进入 M13。
