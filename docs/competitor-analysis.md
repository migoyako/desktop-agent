# 数字分身项目竞品调研

> 调研日期：2026-10-23  
> 调研对象：N.E.K.O、Coopanion、Cyrene-Agent、shunguang-companion、AAAAGENT  
> 目标：判断哪些设计可以直接复用，哪些只能学习思路，以及它们如何映射到“Python 桌面智能体 + 长期记忆 + 电脑操作 + 情绪陪伴”的产品。

## 1. 结论先行

不建议直接 fork 或整体移植这五个项目。更合适的路线是：

1. 保留当前 `agent_framework` 作为最小 Agent 内核，逐步增加持久化、权限、桌面 UI 和陪伴状态。
2. 以 N.E.K.O 的记忆生命周期作为长期记忆的理论基线。
3. 以 shunguang-companion 的 Python 文件任务实现作为本地执行安全基线。
4. 以 Cyrene-Agent 的模式隔离、风险分级和主动聊天冷却作为交互策略基线。
5. 以 Coopanion 的桌宠体验、人格文件版本化和确认策略作为产品体验参考。
6. 以 AAAAGENT 的情绪快照、记忆衰减和工作回执作为数据契约参考。
7. 第一阶段只做一个端到端垂直切片，不同时开发五个大模块。

最终产品不应只是“桌面上多了一个会聊天的窗口”，而应形成四个闭环：

- 认知闭环：对话 -> 记忆候选 -> 用户确认/纠正 -> 后续召回。
- 执行闭环：意图 -> 规范化动作 -> 权限判断 -> 确认 -> 执行 -> 回执 -> 可撤销。
- 情绪闭环：观察 -> 状态更新 -> 表达 -> 用户纠错 -> 状态修订。
- 关系闭环：共同经历 -> 时间线 -> 回顾 -> 遗忘与边界控制。

其中“执行闭环”和“认知闭环”必须优先完成，否则桌面形象和情绪表达只是没有真实能力的外壳。

## 3. 各项目深入分析

### 3.1 N.E.K.O：最完整的 Python 记忆与电脑操作参考

关键路径：

- `docs/zh-CN/architecture/memory-system.md`
- `brain/computer_use.py`
- `brain/task_executor.py`

值得吸收的设计：

- 记忆不是一个向量库，而是分层流水线：
  - 工作上下文
  - 近期原始对话
  - 事实
  - 反思
  - 人格知识
- 原始消息、事实、反思和人格的写入路径、保留规则及提示词注入方式不同。
- 新事实先去重，再作为证据强化或反驳已有记忆。
- 反思有 `pending`、`confirmed`、`promoted`、`negated`、`archived` 等生命周期。
- 人格记忆有 protected 条目，不会因为普通证据衰减被删除。
- BM25、向量和 RRF 融合召回；向量不可用时仍能退回 BM25。
- 时间召回是独立能力，可回答“上周二我们聊了什么”。
- 后台任务通过 outbox 和幂等重放提升可靠性。
- 上下文优先装入最近完整轮次，再装摘要和长期记忆，不会跳过一大段最近对话拼接孤立旧消息。
- 浏览、搜索和策略预览不会强化记忆；只有用户明确重提或确认才强化。
- 记忆浏览器支持查看来源、纠正、遗忘和实际召回记录。

不建议照搬：

- 多进程服务拆分对早期项目过重。
- JSON 视图、SQLite、事件日志、后台协调器并存，会显著提高一致性成本。
- 前端和运行时组合较重。
- 其电脑操作能力需要单独做安全审查，不能因为项目流行就默认安全。

对本项目的落地方式：

- 第一阶段用单个 SQLite 数据库保存事件、记忆和任务，不拆微服务。
- 保留 `source_message_id`、原话片段、置信度、作用域和状态。
- 在记忆浏览器里显示“为什么想起这件事”，并提供忘记和纠正。

### 3.2 Coopanion：最成熟的桌宠产品体验参考

关键路径：

- `core/persona.ts`
- `core/notice.ts`
- `docs/DEVELOPMENT.md`

值得吸收的设计：

- 桌宠不是聊天窗口的皮肤，而是完整交互宿主：气泡、位置、走动、互动、状态图标和输入方式都围绕桌面场景设计。
- 人格有明确边界：`CONSTITUTION.md` 保存角色底线，`PARTNER.md` 保存对用户的理解，细节文件单独管理。
- 用户画像和工作区每次修改都形成版本，用户可以查看历史。
- 电脑操作有从严格到宽松的四档策略：
  - 每轮都问
  - 动手前问
  - 一段时间内只问一次
  - 从不询问
- 用户接管鼠标/键盘时立即停止自动操作。
- 登录、密码、付款始终交给用户。
- 用状态气泡显示“思考、读文件、搜索、写入、操作电脑”，让执行过程可感知。
- 语音优先本地识别；需要发给模型的内容有隐私说明。

不建议照搬：

- Electron/TypeScript 主栈与 Python 规划不一致。
- AGPL 影响后续许可证选择。
- 桌宠 World 和插件体系不是 MVP 必需。
- 四档确认可以借鉴，但默认值应比消费级桌宠更保守，建议初期默认 `ask-before-acting`。

### 3.3 Cyrene-Agent：模式隔离与权限策略最值得直接学习

关键路径：

- `src/main/permission-policy.ts`
- `src/main/proactive/proactive-policy.ts`
- `src/main/memory/memory-types.ts`
- `docs/design/2026-10-02-global-wiki-memory-design.md`

值得吸收的设计：

- Chat 模式默认完全不暴露工具，避免聊天中的比喻或角色化表达误触发文件操作。
- Work/Code/Learn 模式按需装载不同工具集和权限。
- 风险按 `safe`、`fs-read`、`fs-write`、`shell`、`network`、`input-control` 分类。
- 工作目录必须预先绑定，模型不能自行切换。
- `..`、符号链接和路径逃逸都要检查。
- 同一会话只允许一个执行任务，避免多个工具互相踩状态。
- 任务可被用户接管并保留 checkpoint。
- 主动聊天默认策略：
  - 普通对话结束后 30 分钟静默期
  - 两次主动沟通至少间隔 2 小时
  - 未回复追问至少间隔 6 小时
  - 连续 2 次未回复后停止
  - 夜间、锁屏、对话忙或生成忙时不发起
- 记忆具有全局/工作区作用域，遗忘需要在依赖关系中传播。
- 消息、记忆和情绪都具有来源证据链。

对本项目的落地方式：

- 将模式、风险和工具注册表做成显式配置，不靠提示词约束模型“不要调用”。
- 在工具真正暴露给 LLM 之前进行过滤。
- 主动聊天策略实现为纯函数，便于单元测试和解释“为什么现在不说话”。

### 3.4 shunguang-companion：Python 执行层的最佳工程参考

关键路径：

- `backend/app/filework.py`
- `backend/app/memory.py`
- `backend/app/credentials.py`
- `backend/app/rag.py`
- `backend/app/retrieval_router.py`

值得吸收的设计：

- 工作目录必须由用户显式授权，不接受磁盘根目录和网络共享。
- 拒绝符号链接、Windows 目录联接/重解析点、硬链接和跨挂载目录。
- 阻止 `.env`、`.git`、凭据目录和内部管理目录被访问。
- 使用规范化路径检查 Windows 保留名称、ADS、尾随点/空格和非法字符。
- 修改前记录 SHA-256、大小和权限；执行前再次校验，防止覆盖其他程序的新修改。
- 新建文件使用独占移动，避免覆盖竞态。
- 删除需要单独审批，覆盖前备份，任务可恢复。
- 文件任务串行执行，最多 50 步，并有取消和超时。
- 记录每一步的 before/after 状态，支持崩溃后的幂等恢复。
- API Key 在 Windows 使用 DPAPI，其他平台使用系统钥匙串，无明文降级。
- BGE-M3 + Qdrant 放在隔离 worker 中，文档索引与陪伴记忆分离。
- RAG 回答显示引用，人物设定、世界知识和个人记忆分别路由。

不建议照搬：

- 当前是非商业许可，不能把实现直接用于商业产品。
- BGE-M3 对普通桌面应用过重，首次安装和 CPU 检索体验成本高。
- 只接受 UTF-8 文本的文件读取不覆盖 Office/PDF 等办公场景。
- 文件 API 不是进程沙箱，Shell 和浏览器仍需另设边界。

对本项目的落地方式：

- MVP 只支持授权工作区、文本文件、显式写入和回执。
- 文件系统是权威数据源，向量索引只是可重建缓存。
- 任何文件写入都先形成 action proposal，再执行。
- 删除、覆盖、移动和批量写入单独提升权限等级。

### 3.5 AAAAGENT：记忆动态和情绪数据契约最成熟

关键路径：

- `docs/MEMORY.md`
- `code/desktop-pet/contracts/emotion-state.ts`
- `code/desktop-pet/memory/dynamics.ts`
- `code/desktop-pet/harness/receipts.ts`

值得吸收的设计：

- 用户情绪估计和角色心情独立保存。
- 一条消息保存当时的情绪快照，后续分析不能改写历史快照。
- 情绪状态包含来源、置信度和强度；未知强度用 `null`，不能用 `0` 伪装成“没有情绪”。
- 记忆衰减公式：
  - 活动半衰期：`30 × (1 + 2I)` 天
  - 情绪半衰期：7 天
  - 优先级：`C × (0.55 + 0.25A + 0.15I + 0.05E)`
  - 激活阈值：`0.35`
  - 强化：`A' = A + 0.2 × (1 - A)`
- 人格和稳定档案不随时间衰减，普通事件才衰减。
- 工作回执有版本、幂等键和原始输入，未知结果和未发送状态明确区分。
- 任务回执不可被后续模型回复覆盖。

不建议照搬：

- 自定义非商业许可。
- 代码体积和本地模型运行时不适合作为 Python MVP 基础。
- 完整动态系统如果一开始全量实现，会淹没核心任务执行能力。

对本项目的落地方式：

- 先采用同样的公式和字段语义，但只实现最小状态机和 SQLite 表。
- 每条情绪判断都必须能被用户查看、否定和重新解释。
- 任务执行结果必须由执行器写回执，不能由 LLM 声称成功。

## 4. 功能的取舍

### 4.1 直接进入第一版

- PySide6 透明桌面窗口。
- PNG 序列帧角色，支持待机、思考、说话、开心、困惑五种状态。
- 文本聊天和流式回复。
- Chat/Work 两种模式，Chat 默认无工具。
- “搜索网页并保存为笔记”这一条完整任务链。
- 动作提案、用户确认、执行状态和持久化回执。
- SQLite 保存原始对话、共同经历、用户偏好和任务记录。
- 记忆来源查看、纠正和忘记。
- 基础情绪状态和可解释的主动聊天节流。

### 4.2 后续再做

- 完整 Live2D。
- 实时语音对话和声音克隆。
- 多显示器复杂交互。
- 浏览器复杂自动化。
- 多角色、多用户、多设备同步。
- 自动写文件、自动执行 Shell 的“全自动模式”。
- 基于本地大模型的完全离线推理。

### 4.3 暂缓或不做

- 一开始就拆分五个微服务。
- 一开始就接入大型 BGE-M3。
- 让模型自行决定并跳过权限确认。
- 用单一 `mood` 数值代表所有情绪。
- 把向量数据库当作事实来源。
- 无上限的“自我反思”和人格自动改写。
- 未经验证的语音克隆或第三方角色素材分发。

## 5. 差异化机会

现有项目各自很强，但很少把以下四点同时做好：

1. **共同经历时间线**：把对话、任务、文件成果和情绪节点放在同一条可回溯时间线上。
2. **可回放、可撤销的任务胶囊**：一次任务包含目标、计划、动作、证据、结果和撤销记录。
3. **人格与权限联动模式**：陪伴、专注、执行、安静不仅是语气变化，还改变工具暴露、主动性和打扰频率。
4. **关系与记忆账本**：用户能看见“它怎么记住的、为什么这样理解、如何纠正和忘记”。

这四点应以“可审计、可控制”为核心，形成与纯角色聊天产品或纯自动化 Agent 的差异。

## 6. 推荐采用的组合

```text
产品体验       Coopanion
模式与权限     Cyrene-Agent
文件执行安全   shunguang-companion
记忆生命周期   N.E.K.O
情绪与回执契约 AAAAGENT
最终实现语言   Python + PySide6 + SQLite
```

需要注意：这只是设计来源的组合，不是代码的直接拼装。尤其是 Coopanion、shunguang-companion 和 AAAAGENT 的代码不能未经授权进入商业发行版。
