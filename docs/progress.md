## 0. 结论

- 横向功能覆盖约 **80–85%**，纵向可靠性、记忆深度约 **30–40%**。
- 当前主要矛盾不是“功能不够”，而是 **执行不可对账、记忆不可追溯**。
- 下一阶段顺序：**M1 可审计执行内核 → M2 证据链记忆 → M3 上下文 → M4 主动陪伴 → M5/M6/M7/M8**。
- 在 M1、M2 完成前，不启动语音、Live2D、多角色和社交渠道。

完成度是工程估算，用于判断趋势，不作为验收标准；验收以第 7 节指标和第 5 节各模块验收条件为准。

| N.E.K.O | 读时衰减证据、反思晋升、BM25 + RRF、outbox/幂等/tombstone、主动门链、工具注册表 | Apache-2.0；三进程架构过重，只取单进程可移植部分 |
| shunguang-companion | 多轮工具循环、证据事实库、文件身份 + 每步指纹、持久化提醒、SSE 流式/停止 | 非商业许可；纯 Web，无桌宠代码 |

五个项目独立收敛出的四条共识：

1. 工具不是函数，而是带风险、状态、回执的事务。
2. 记忆不是向量库，而是“证据 → 候选 → 晋升 → 遗忘”的生命周期。
3. 主动不是定时器，而是“活动状态 → 门控 → 来源 → 反重复”的决策链。
4. 确认不是弹窗，而是绑定世界快照的一次性令牌。

## 5. 模块路线图

### M1 可审计执行内核

- **优先级**：P0
- **状态**：进行中（基础提案/回执已存在）
- **依赖**：无
- **预计**：1–2 周
- **目标**：让每一次工具调用都可授权、可去重、可对账、可恢复。

工作项：

- [ ] 统一 `ToolRegistry`：JSON Schema、按模式装配、单工具超时、结构化结果。
- [ ] LLM 原生工具循环：每轮 `bind_tools`，最多 4 次调用 / 3 轮；不支持 function calling 的模型回退到正则。
- [ ] 工具四态：`success / failure / unknown / not_executed`。
- [ ] `uncertainEffects`：只对已派发且结果不可知的副作用工具产生 `unknown`，记录效果指纹，禁止自动重放。
- [ ] 执行账本：逻辑调用 ID 使用 `proposal_id:step_id` 或 `run_id:tool_call_id`，UNIQUE + in-flight 去重 + 终态成功缓存（TTL 10 分钟）。
- [ ] 提案快照：工作区真实路径、卷序列号/文件 ID、目标路径、内容哈希、模式、风险、TTL、`idempotency_key`。
- [ ] 确认复核：重新校验工作区身份、当前模式、策略和文件哈希；不一致返回 `not_executed`，不写文件。
- [ ] 执行与撤销只读提案/回执快照，不读当前 runtime 工作区。
- [ ] 执行日志：执行前写 intent；重启后把 `running` 标为 `unknown/interrupted`，绝不自动重放。

验收：

- 确认前切换工作区 → 写入被拒绝，回执为 `not_executed`。
- 当前模式已降级 → 旧提案不能越权执行。
- 重复确认/重复请求 → 只产生一次写入，返回同一回执。
- 模拟超时或崩溃 → 状态为 `unknown`，可人工对账，不自动重试。
- 撤销不受当前工作区影响。
- 新增至少 5 个回归测试，原有 34 个测试保持通过。

落点：新增 `agent_framework/companion/execution/`（`harness.py`、`ledger.py`、`journal.py`），修改 `runtime.py`、`file_actions.py`、`policy.py`、`store.py`。

### M2 证据链记忆中心

- **优先级**：P1
- **状态**：进行中（基础事实/情绪已有）
- **依赖**：M1 的稳定消息 ID 与回执 ID
- **预计**：2–3 周
- **目标**：每条长期记忆都能回答“从哪来、为什么信、何时被用过、忘记后去了哪”。

工作项：

- [ ] 版本化迁移：为 `store.py` 引入 `user_version`，新增记忆相关表。
- [ ] 表结构：`memory_facts`、`memory_evidence`、`memory_candidates`、`memory_events`、`recall_log`、`memory_tombstones`、FTS5 虚表。
- [ ] 抽取：只从用户消息抽取；证据必须是原消息子串，值必须是证据子串；助手回复不能单独证明用户事实。
- [ ] 规范键：使用“类别·主语”拆键，避免不同偏好互相覆盖。
- [ ] 冲突与晋升：加权评分（用户纠正、近期、双证据、归档、无证据），高分自动晋升，中间分进候选，低分归档；合并保留 `merged_from_ids`。
- [ ] 召回：FTS5/BM25 + 中文 2/3-gram；作用域、时间、状态过滤；返回 6–8 条并附来源与原因。
- [ ] 召回日志：记录 `query_hash / fact_ids / scores / used_in_reply / latency`，不存敏感原文。
- [ ] 遗忘：tombstone + `forget_epoch` + `through_seq`；召回、摘要、导入统一过滤；依赖该事实的派生记忆失效。
- [ ] 衰减：只采用一套读时公式（N.E.K.O 的 `rein*0.5^(age/30d) - disp*0.5^(age/180d)`）；人设类事实 `protected` 永不淘汰。
- [ ] 导入：旧聊天导入可暂停续跑、跨副本去重、已遗忘内容不复活、导入前提示成本。

验收：

- 派生记忆来源覆盖率 100%，每条都能跳到原始消息或回执。
- 仅由助手回复推导的“用户事实”被拒绝。
- 召回结果带来源和原因；`recall_log` 有记录。
- 用户纠正后，旧值不再被召回。
- 遗忘后，直接召回、摘要和导入都不会复活。
- FTS5 损坏或召回异常时，聊天主流程不受阻塞。

落点：新增 `agent_framework/companion/memory/`（`facts.py`、`evidence.py`、`recall.py`、`lifecycle.py`、`forgetting.py`），保留现有 `memory.py` 作为迁移入口。

### M3 上下文编排器

- **优先级**：P1
- **状态**：未开始
- **依赖**：M1、M2
- **预计**：3–5 天
- **目标**：在固定预算内稳定组装“人设 + 近期完整轮次 + 摘要 + 召回记忆”。

工作项：

- [ ] 提示词分层：稳定人设 / 会话前缀 / 运行时上下文 / 模式；稳定层做哈希指纹。
- [ ] 工具 Schema 按名称排序，保持前缀稳定。
- [ ] 上下文预算：最近完整轮次 + 摘要 + 召回记忆，超限按优先级裁剪。
- [ ] 压缩：80–85% 触发，切点避开 `tool_call/tool_result` 对，写 checkpoint 摘要。
- [ ] 工具输出：超过 16–30KB 落盘，只回 `ok/truncated/preview` 与句柄，需要时用 `read_tool_result` 回读。
- [ ] 明确“未返回内容不算已读”，防止模型臆断。

验收：预算内不超限；压缩后工具调用对完整；大输出可回读；相同稳定前缀哈希一致。

落点：`agent_framework/companion/context.py`，由 `runtime.py` 调用。

### M4 主动陪伴引擎

- **优先级**：P1
- **状态**：未开始
- **依赖**：M2 的活跃记忆、M3 的上下文
- **预计**：1 周
- **目标**：有理由、有预算、可关闭地主动说话。

工作项：

- [ ] 活动状态机：`idle / away / private / focus / game`；Windows 使用 `GetLastInputInfo`、`GetForegroundWindow`、`psutil`。
- [ ] 门控链：Quiet 模式 → 免打扰时段 → 每日最多 2 次 → 间隔至少 3 小时 → 有未回复则阻断 → 隐私门。
- [ ] 来源：提醒、未完成话题、活跃记忆事件；不使用随机话题。
- [ ] 反重复：按来源类型半衰期 + 内容/URL 哈希去重，重复则丢弃或重生成。
- [ ] 持久化：`next_due / last_event_id / quiet_hours`；错过的主动消息不补发，只标未读。
- [ ] 记录每次主动发言的触发原因，并可在 UI 查看。

验收：Quiet/免打扰不发言；每日与间隔上限生效；连续未回复后停止；错过不补发；触发原因可追溯。

落点：`agent_framework/companion/proactive/`，复用现有 Quiet 模式与 `QTimer`。

### M5 工作任务卡与计划模式

- **优先级**：P2
- **状态**：未开始（现有 work 模式是固定“搜索 → 笔记”流程）
- **依赖**：M1
- **预计**：1–2 周
- **目标**：把开放式工作请求变成可审阅、可修改、可拒绝的任务卡。

工作项：

- [ ] 意图路由：`companion / work / clarify`，12 秒超时，抗提示注入。
- [ ] 任务卡：标题、理由、口语播报、目标、执行器、项目。
- [ ] 计划状态机：`NORMAL / PLAN_DISCUSSING / PLAN_REVIEW / EXECUTING`；先落库再等待。
- [ ] 审批卡：approve / revise / reject；超时绝不默认通过；崩溃恢复为 discussing。
- [ ] 转发回执：`awaiting_confirmation / forwarding / accepted / completed / unknown / unavailable`；`unknown` 不自动重发。

验收：信息不足只追问一次；未确认不产生外部副作用；超时不自动通过；崩溃可恢复；`unknown` 不重复发送。

### M6 桌面形象与流式交互

- **依赖**：M1 的工具状态事件
- **预计**：1–2 周
- **目标**：让桌宠状态来自真实执行器，而不是模型自述。

工作项：

- [ ] 托盘：`QSystemTrayIcon`，显示当前模式、暂停主动、退出。
- [ ] 透明置顶窗口：`FramelessWindowHint | Tool | WindowStaysOnTopHint` + `WA_TranslucentBackground`。

## 7. 验收指标

| 指标 | 含义 | 目标 |
|---|---|---|
| 越权执行次数 | 未授权写入、越界路径、未确认高风险动作 | 0 |
| 回执完整率 | 执行动作有结构化回执的比例 | 100% |
| `unknown` 对账率 | 不确定状态最终有结论的比例 | 100% |
| 重复执行次数 | 同一幂等键产生多次副作用 | 0 |
| 记忆来源覆盖率 | 派生记忆可追溯到来源的比例 | 100% |
| 召回可解释率 | 召回结果带来源与原因的比例 | 100% |
| 遗忘传播完整率 | 原文、记忆、索引、派生状态同步处理 | 100% |
| 重启恢复率 | 重启后可查看/撤销的任务比例 | 可恢复任务 100% |
| 主动打扰拒绝率 | 用户关闭或忽略主动发言的比例 | 持续观测并调阈值 |
| 测试基线 | 每次合并前的单元测试 | 全绿，且新增模块有回归用例 |

不把“聊天时长”作为核心成功指标。健康指标应包含用户控制感、任务有效性和打扰可接受度。
