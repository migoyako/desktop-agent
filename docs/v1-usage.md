## 启动前检查

支持的主要场景是 Windows 桌面端。推荐 Python 3.12，项目测试基线也是 3.12；Python 3.11 以上可以运行安装脚本。Windows 10/11 的标准用户桌面环境是推荐环境。

安装脚本会安装：

- PySide6 与 Qt WebEngine；
- OpenAI SDK；
- PyAutoGUI、pywinauto、pygame 与 Pillow；
- Playwright 与 Chromium，用于浏览器回归和界面验证。

不需要另外安装文件索引、应用目录、回收站、启动链或 MCP 的“Agent 驱动”，这些都在 `agent_framework/companion/` 内实现。需要自己准备的是模型 API、可选的 MCP 服务器、角色素材和可选的 OpenClaw Gateway。

先确认：

1. 当前账户能正常登录 Windows 桌面；
2. 能访问模型服务和依赖下载源；
3. 项目目录不是只读目录；
4. 不要从受限沙箱或 IDE 内置终端启动；
5. 没有把 API Key、真实数据库或私人素材放进 Git。

`doctor.py` 会检查 Python、进程完整性、数据库、实例锁、授权、文件索引、应用启动和角色素材。它显示 WARN 不一定是故障，例如尚未创建数据库或尚未配置角色素材都属于可用状态。

## 安装与启动

在项目根目录双击 `setup.cmd`。它实际调用 `setup.ps1`，并支持传入 Python 包索引参数：

```powershell
.\setup.ps1 -IndexUrl "https://pypi.tuna.tsinghua.edu.cn/simple"
```

脚本会创建仓库外的虚拟环境，通常位于：

```text
C:\Users\Public\CompanionRuntime\venv
```

仓库里的 `.venv` 只是 junction（目录联接）。这样做是因为 Windows 会继承可执行文件的完整性标签；把 Python 放在受限的仓库目录里，可能出现“读文件正常、写文件 Permission denied”的情况。重新运行 `setup.ps1` 是幂等的，也可以修复被移动到仓库内的旧环境。

安装完成后：

```powershell
.\run.ps1
```

或者双击 `start_companion.cmd`。启动脚本会做下面两项检查：

- 当前终端是否带 Low integrity 标签；
- `.venv\Scripts\pythonw.exe` 是否带 Low Mandatory Level。

任一项命中都会拒绝启动。此时不要通过降低安全检查或直接运行 `pythonw.exe` 绕过；关闭终端，在资源管理器中双击 `start_companion.cmd`，或重新运行 `setup.ps1`。

可选启动方式：

```powershell
.\run.ps1 --ui browser        # 仅使用默认浏览器
.\run.ps1 --ui cli --offline  # 无图形界面的离线命令行
.\run.ps1 --ui qt             # 兼容用 Qt 界面
.\run.ps1 --ui tk             # 兼容用 Tk 界面
```

默认数据目录是 `data/`，可以指定另一个目录：

```powershell
.\run.ps1 --data-dir D:\CompanionData
```

每个数据目录默认只允许一个实例。再次启动时，程序会尝试唤回已有实例，而不是启动第二套数据库。

## 配置模型服务

模型必须提供 OpenAI 兼容的聊天接口。最小配置是：

```json
{
  "OPENAI_API_KEY": "你的 API Key",
  "OPENAI_BASE_URL": "https://your-provider.example/v1",
  "MODEL_NAME": "model-name"
}
```

文件位置是项目根目录下的 `config/keys.json`。不要提交它，项目已通过 `.gitignore` 忽略。

也可以从界面配置：

1. 点击左下角 **设置**；
2. 进入 **模型 → 模型推理**；
3. 点击 **服务接入**；
4. 填写 Base URL、API Key，点击 **拉取模型**；
5. 选择模型并保存。

拉取模型需要网络和服务端兼容 `/models`。上游不返回上下文窗口时，使用设置页的窗口输入框手工填写。服务接入会同时更新本地配置与应用设置，API Key 在界面中只以掩码显示。

离线模式：

- 点击设置里的 **离线模式**，或启动时使用 `--offline`；
- 不调用远程模型，适合检查界面、管理本地数据和测试权限；
- 不组装正常的模型回答，不要把离线时的结果当成真实模型能力；
- 命令行强制离线时，即使设置里保存了在线开关，当前进程仍然保持离线。

模型请求、网页搜索和 MCP 外部调用都可能出站。公司代理、防火墙、证书拦截或 DNS 失败会导致请求失败；程序应显示错误，而不是把失败冒充为成功。

## 第一次使用

推荐先完成一次“只读”流程：

1. 启动并完成模型配置，或者切到离线模式；
2. 进入 **设置 → 桌面 → 授权目录**；
3. 选择一个测试文件夹，例如 `D:\CompanionTest`；
4. 只勾选 **读取** 和 **搜索**；
5. 点击 **授权并索引**，等待索引完成；
6. 回到主界面，切换到 **工作** 或 **执行**；
7. 输入“在已授权的目录里找一下包含 report 的文件”。

如果这一步正常，再逐步授权写入和应用启动。不要一开始就授权整个用户目录、磁盘根目录或系统目录。

选择工作目录不等于文件授权。工作目录用于笔记和任务上下文；文件工具需要设置页中明确的 `fs-read`、`fs-search`、`fs-write` 或 `fs-delete` 能力。没有对应能力时，工具不会出现在模型可用清单里。

## 界面与模式

主界面默认分为三部分：

- 左侧是会话、搜索、工作区和设置；
- 中间是对话、工具回执与审批卡；
- 右侧是执行、文件、来源、上下文和任务详情。

输入框上方的运行条会显示正在思考、调用工具、生成回答、等待审批、完成、取消或失败。至少两步的操作可以展开步骤时间线。

四种模式的安全边界不同：

| 模式 | 适合做什么 | 安全边界 |
| --- | --- | --- |
| 陪伴 | 聊天、记忆、情绪和提醒 | 不开放网页搜索、文件写入和桌面执行 |
| 工作 | 搜索、笔记、文件检索和常规任务 | 需要相应授权；文件工具只在工作模式出现 |
| 执行 | 文件操作、应用启动、启动链 | 仍受授权、风险和确认规则约束 |
| 安静 | 尽量少打扰 | 不开放高风险执行工具，主动消息减少 |

权限档位只决定“是否先询问”和哪些工具可见，不会把 DENY 变成 ALLOW：

- **保守**：禁用文件写入，应用启动等高风险工具受限；
- **平衡**：显式 `fs-write` 目录里的写入可以直接走审计执行链；
- **信任**：写入自动化更宽，但删除、启动链和外部调用仍有各自边界。

建议先使用平衡档，确认回执、备份和撤销流程后再调整。

## 桌面能力

### 授权目录

打开 **设置 → 桌面 → 授权目录**。选择目录后，分别确认能力：

- **读取**：允许读取目录内文本；
- **搜索**：允许使用文件元数据索引查找候选；
- **写入**：允许新建、覆盖、移动和重命名；
- **移入回收站**：允许删除操作进入系统回收站。

授权只覆盖这个目录，不自动覆盖其父目录或整个磁盘。新增、移动文件后可以点 **重建索引**。撤销授权不会删除目录里的文件，只让后续工具立即失去权限。

### 搜索与读取

在工作/执行模式下，模型可以：

- 用 `find_files` 返回最多 5 个候选，先给名称、路径等元数据；
- 用 `read_file` 读取候选文件的分段文本，不接受任意绝对路径；
- 读取前检查授权、文件身份和路径边界；
- 对非文本文件给出拒绝或只返回元数据，不会把二进制内容当文本塞进上下文。

搜索结果有数量上限。模型不应把“候选最多 N 个”说成“目录只有 N 个文件”。

### 写入、移动与删除

写入和移动需要目标目录有显式 `fs-write` 能力。执行前会复核目录身份、参数、授权与有效期；目录被换掉、授权被撤销或目标文件状态变化时会拒绝执行。

覆盖前会创建本地备份并记录回执。新建文件可以撤销，覆盖操作可以恢复到备份版本。备份有大小上限，超过上限时会明确说明不可撤销。

删除需要 `fs-delete`，并且只调用 Windows 回收站：

- 不提供永久删除工具；
- 网络共享路径、路径过长、空参数等情况会在执行前拒绝；
- 删除失败时文件应仍在原处；
- 删除后如果从回收站清空，程序无法再恢复。

### 应用目录与启动

打开 **设置 → 桌面 → 应用目录**：

1. 点击 **扫描本机应用**；
2. 查看名称、路径、发布者和签名状态；
3. 只对可信应用点击 **允许启动**；
4. 也可以用 **登记并允许启动** 手动填写目标和名称。

扫描只发现应用，不等于授权。允许启动后，工作/执行模式下模型可以通过 `open_app` 启动这个目标。模型不能传任意命令行参数；参数来自应用目录记录。启动前会重新检查目标是否仍是登记时的文件和发布者，身份发生漂移会拒绝并要求重新登记。

启动回执可能包含进程号，但**应用启动不可撤销**：程序可能在启动后已经写入文件或创建子进程。不要对不熟悉的程序授予启动权限。

### 启动链

启动链用于“先打开一个应用，再由它触发另一个应用”的场景。起点和终点都需要先登记，并且至少一个应用需要具备启动授权。

可用触发方式包括：

- `auto`：按进程、窗口和规则检测；
- 固定参数；
- URI Scheme；
- 已登记 API；
- 人工接管；
- Windows UI Automation。

推荐流程：

1. 在 **启动链** 新建配置；
2. 选择起点应用和目标应用；
3. 配置触发方式、等待时间与目标窗口规则；
4. 点击 **检测链** 做预检；
5. 从对话或设置页生成执行提案；
6. 确认后查看回执和“是否确认新实例”的结果。

UI Automation 只操作启动器进程内唯一匹配窗口，不接受坐标控制。已有目标实例默认不会被当作本次启动成功；只有明确配置复用才允许。超时、多候选、窗口不可见或无法确认时，回执会写“已启动但无法确认”，不会虚报成功。

## 文档库与 MCP

### 文档库

当前文档库支持：

- `.md` / `.markdown`；
- `.txt`；
- `.csv`；
- `.json`；
- `.log`；
- `.docx`（内置转换为 Markdown）。

不支持 PDF、旧版 `.doc`、`.rtf`、`.odt`、`.docm` 和 `.dotx`。导入前会检查大小、编码、文件类型、归档结构和内容安全条件；拒绝发生在写入之前。

当前文档库的后端与 `/api/docs` 接口可用，可以通过 `GET /api/docs` 查看列表、向 `POST /api/docs/import` 发送文档内容、向 `POST /api/docs/delete` 发送文档 ID。**Web 设置页还没有上传和列表按钮**，所以普通用户暂时不要把这里当成拖拽上传入口；日常使用优先通过已授权目录的 `find_files` / `read_file` 读取本地文档。文档命中会作为“来源”显示在对话上下文里，删除会话或清空记忆不会删除文档库。

### MCP

MCP 是可选的 MCP 服务器客户端，支持：

- `stdio`：本地命令作为子进程；
- `streamable HTTP`：远程 HTTP 服务，兼容 JSON 与 SSE 响应。

添加和连接：

1. 进入 **设置 → 模型 → MCP 服务**；
2. 添加服务器，选择 stdio 或 HTTP；
3. 填写命令/参数或地址；
4. 点击 **连接并获取工具**；
5. 逐条打开需要的工具。

刚添加的服务器默认不开放工具。工具调用属于外部副作用：陪伴/安静模式不可用，保守档拒绝，其他模式需要确认。凭据保存在 `config/mcp_keys.json`，不会写入数据库或备份；如果使用 stdio，命令本身需要由你安装并维护。

MCP 调用没有本地回滚能力，回执会明确写明不可撤销。不要连接来源不明的服务器，也不要把长期凭据交给不必要的工具。

## 提醒记忆与任务

### 提醒

以下说法会直接生成本地提醒：

```text
提醒我 10 分钟后喝水
半小时后提醒我站起来
明天早上 7 点提醒我开会
18:30 提醒我取快递
```

提醒支持秒、分钟、小时、天、中文数字和常见钟点写法。解析不出的表达可以交给模型的 `set_reminder` 工具。提醒到点后进入提醒面板，不会因为模型离线而消失。

### 记忆

记忆保存在 SQLite 中。设置里的 **对话记忆与交互** 可以查看、纠正和清空记忆。清空记忆通常不会删除人设、文档库或全部备份；“彻底清理”是单独的危险操作。

旧聊天可以通过 JSON/JSONL 导入。导入会先显示规模和预计成本，支持暂停和续跑；角色扮演会话只导入消息，不抽出用户事实；“忘记”会写入墓碑，阻止相同内容被召回。

### 任务和计划

涉及副作用的请求可能先进入工作任务卡。任务会经历讨论、审阅、执行等状态；信息不足时只追问一次。审批有效期有限，超时不会自动执行。崩溃恢复后，执行状态不确定的任务会标为 `unknown`，不会自动重放。

## 人设与桌宠

默认人设位于：

```text
data/personas/remielle/
```

人设文件包括 `persona.json`、`persona.md`、`facts.md` 和可选的 `worldbook.md`。缺失或损坏时回退为朴素助手，不阻止主程序启动。

素材放在：

```text
data/assets/<persona_id>/
├── avatar.png|webp|jpg
├── background.png|webp|jpg
├── avatar.mavatar
└── live2d/
    └── model3.json
```

- 有 `live2d/model3.json` 时优先用 Live2D；
- 没有 Live2D 时可以放 `avatar.mavatar`；
- 两种素材都没有时，聊天、文件工具和普通界面仍正常，只是透明桌宠浮窗不启动；
- 素材损坏时不会静默切换成另一种形象，设置页会显示原因；
- 用户素材通常有独立许可，不应上传到公开仓库。

头像、背景和桌宠的细节入口在 **设置 → 数据与外观**。背景清除只关闭显示，不删除原始图片。

## 微信接入

微信/ClawBot 不是主程序的必需功能。典型链路是：

```text
微信 → ClawBot → OpenClaw Gateway → agent_service.py
     → data/.companion.endpoint → 正在运行的桌面主程序
```

启用前必须：

- 安装并运行 OpenClaw Gateway 与 ClawBot；
- 桌面主程序保持运行；
- 桥接服务和主程序使用同一个数据目录；
- 让 OpenClaw 能访问本机桥接端口；
- 不要让多个实例同时写同一个数据库。

桥接的模型、离线和权限设置来自桌面程序。微信发起的写入、启动和外部调用仍受桌面端的授权与确认逻辑约束，未确认的提案需要在桌面界面处理。

完整命令见 [OpenClaw 桥接文档](../integrations/openclaw/README.md)。

## 数据管理与安全

默认数据位置：

```text
data/companion.db
data/docs/
data/assets/
data/personas/
data/backups/
data/tool_results/
data/ui_state.json
```

备份与导出：

- 管理台可以创建数据库备份并显示清单和校验信息；
- 备份包含业务数据，不包含 `config/keys.json` 和 `config/mcp_keys.json`；
- 导出用于迁移或检查，不应把导出文件上传到公共仓库；
- 数据库升级前可能自动创建迁移前快照。

安全原则：

1. 只授权实际需要的最小目录和最小能力；
2. 写入、删除和启动应用前查看目标与回执；
3. 不要把 API Key、用户素材、真实数据库、日志或备份提交到 Git；
4. 不要在不信任的终端里运行程序；
5. 远程 MCP 和应用启动不是本地回滚动作；
6. 发现误授权后立即在设置页撤销并检查回执。

## 常见问题

### 双击后完全没反应

先从 PowerShell 运行：

```powershell
.\run.ps1 --ui cli --offline
```

如果命令行能启动，问题通常在 Qt WebEngine 或窗口壳层；如果命令行也失败，运行：

```powershell
.venv\Scripts\python.exe doctor.py
```

检查是否已有实例、Windows 托盘是否隐藏了窗口，以及终端是否为受限上下文。

### 提示权限不足或写入失败

常见原因：

- 从 IDE 或沙箱终端启动，进程是 Low integrity；
- `.venv` 被复制回仓库，执行文件继承了限制标签；
- 目录没有授予 `fs-write`；
- 目标是网络共享、路径过长或目录已被替换；
- 当前模式或权限档位禁用了写入。

优先重新运行 `setup.ps1`，然后从资源管理器双击启动。不要用管理员权限盲目放大目录范围。

### 模型连接失败

检查 Base URL 是否以服务要求的版本路径结尾，确认 API Key 有模型和聊天权限，模型名与服务端列表一致。若使用代理或公司网关，确认环境允许出站 HTTPS，且证书没有被拦截。

### 文件搜索没有命中

检查授权目录和索引状态，等待索引完成，或点击 **重建索引**。搜索只返回授权目录内的元数据；二进制文件和被排除的数据目录不应被当作文本搜索对象。

### 回收站删除失败

检查路径是否超过系统 Shell 长度限制、是否在网络共享、文件是否被其他程序占用。失败表示动作没有完成，文件仍在原位置；程序不会自动改成永久删除。

### 应用启动被拒绝

应用可能没有登记、已经被撤销、文件路径变了、发布者变了，或当前模式/档位不允许启动。先重新扫描或登记；身份漂移时不要直接关闭检查，而应确认文件来源后重新授权。

### MCP 连接成功但模型没有工具

连接成功后工具默认全部关闭。打开需要的单个工具或使用全开，再确认服务器仍连接、工具名称没有和其他服务器冲突。
